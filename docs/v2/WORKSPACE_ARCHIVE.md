# Portable workspace archives

`stepdoc/workspace@1` is an additive archive envelope; guide records remain `stepdoc/guide@1` and single-guide `stepdoc/bundle@1` archives remain supported. No guide-data migration is required. A future incompatible envelope must use a new format version and an explicit importer migration.

The `.stepdoc` ZIP contains only `manifest.json` and consecutively numbered `guides/1.stepdoc` through `guides/500.stepdoc`. The strict manifest in `packages/schema/src/workspace.ts` names each nested guide bundle and its SHA-256. Nested bundles retain their existing guide schema, image hashes and redacted editable sources. Empty workspaces contain an empty manifest list. Archives are limited to 500 guides and 256 MiB; the importer also bounds retained expanded guide/image data, ZIP entries, metadata, individual image dimensions and inflated lengths. Unknown paths, traversal, duplicate identities, altered hashes and extra manifest fields are rejected before any restore writes.

W07 exports current visible guides and redacted images using the active storage adapter. It reads every pagination page, bounds and rejects repeated cursors, and checks the listing and guide versions again before producing the download. A detected source change cancels the export; the client cannot provide a database snapshot spanning concurrent edits. Trash, version history, accounts, session cookies, API tokens and server configuration are excluded. The existing client image worker performs redaction before bytes enter the archive. No server image processing or new Storage API endpoint is involved.

Library Import recognizes both workspace and single-guide bundles. It verifies the complete workspace before writing, then restores each guide under a fresh identity, with the public ID cleared and public publishing disabled. Existing guides are never overwritten. Cancellation or a storage failure stops further copies; completed copies remain in the library and the activity log reports how many completed. Restore is not a cross-guide database transaction. An acknowledged in-flight copy uses the existing single-guide cleanup path. If a server commits but its acknowledgement is lost, inspect the destination library before retrying.

Migration currently uses export followed by Import in the destination library, including the compiled extension's offline workspace. The source remains in place. Cloudflare and Node migration controls stay disabled until those targets ship. W07 reports only capabilities returned by the connected `/health`; browser quota is a native estimate and server usage is explicitly unreported when absent.
