# Recorder state ordering

The private capture protocol now carries `stateRevision`. This is an additive field in `stepdoc/capture@1`; guide@1 and the Storage API are unchanged. Existing capture caches without a counter read as revision zero. The first capture-state write upgrades the cache by atomically persisting its snapshot and a safe integer counter. A serialized writer advances beyond the persisted counter, its own last committed counter and the current clock. Persisted ordering survives a service-worker restart and clock rollback; an invalid counter is replaced rather than copied into a message. Unsafe integer overflow rejects the write.

Both background broadcasts and direct source-readiness messages carry the same committed revision. A content recorder rejects an older revision, including delayed Cancel, Pause, or Start messages from a retired session. Versioned initial state reads use the same ordering check. Legacy unversioned initial reads retain the existing response-generation guard. No typed values, URLs or images are added to the state projection.

State broadcasts are notifications: they do not wait for content-script response ports. Start and Resume instead use the existing two-second per-producer readiness barrier, covering every frame in the validated camera scene. Resume rechecks its session and paused phase while holding the capture writer, preventing a cancelled or superseded operation from rearming producers.

Pause and Stop recheck the session under the writer before stopping producers and again after draining pending frames. A superseded control cannot change a newer recording or clear its queue. The native suite holds an actual old control's storage read, cancels it, starts a fresh recording through the retained v1 path, then releases the old reply and verifies rejection and continued trusted capture.

Manual-mask display counts are a narrow exception to lifecycle snapshot serialization: the guarded metadata writer commits them separately without advancing `stateRevision`. A delayed mode acknowledgement cannot block a new mask's acknowledgement. Privacy invalidation occurs synchronously before any storage wait, and the compositor collects actual masks afresh; the display count is never the source of image redaction. Counts from a superseded or stopped recording are rejected under the metadata writer.

Regression tests first reproduce stale delivery disabling a newer recorder, restoring the wrong session identity, and undoing a resume. Native extension checks deliberately replay actual old background messages after a new Start and Resume, while real notification response ports remain unsettled; current trusted actions must still be recorded once with masked pixels and variable/secret references.
